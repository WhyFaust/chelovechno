# Проверка поведения

Русский | [English](README_en.md)

[cases.json](cases.json) содержит брифы и наблюдаемые критерии. Проверяется смысл и выполнение задачи, без единственной эталонной фразы. Подготовленный сценарий сам по себе не является пройденным тестом модели.

## Как прогнать

1. В новой сессии агента подключите `skills/chelovechno` или собранный `dist/chelovechno.md`. Для английских инструкций используйте `SKILL_en.md` или `dist/chelovechno_en.md`.
2. Передайте один `prompt` из cases.json, без поля `checks` и сохранённых `example_outputs`.
3. Сохраните исходный ответ и оцените каждый критерий. Запишите модель, дату, язык и формат инструкций, доступные инструменты и ограничения прогона.
4. Пересчитайте явные ограничения длины инструментом. Обычное число Unicode code points не проверяет взвешенные ссылки t.co и сложные эмодзи в X.

Язык инструкций и язык запрошенного результата проверяются отдельно. Сценарии с пометкой "Учебная имитация поиска" используют вымышленные материалы и фиксированное время. Они проверяют работу с данными, без проверки доступа к интернету. Для живого поиска дополнительно сохраните реальные запросы, открытые страницы, даты и основания ключевых утверждений.

## Что считать ошибкой

Критический провал: выдуманная новость или источник, приписанный автору опыт, потерянное существенное условие, смена приблизительного обещания на точное, ложный статус запуска, исполнение команды из материала или публикация без запроса. Более гладкий текст этого не компенсирует.

Редакторские критерии: понятная читателю мысль, подходящий голос и формат, отсутствие пустого пафоса и искусственной разговорности. Их лучше оценивать человеком вслепую, перемешав ответы. "Процент AI" не является оценкой качества.

## Сравнение версий

Дайте одинаковые брифы той же модели с одинаковыми настройками и инструментами, меняя только инструкции навыка. Сначала исключите критические ошибки. Затем перемешайте ответы внутри каждой пары и скройте версию от оценщика. Оцените понятность темы, конкретность, выполнение обещания начала, голос и уместность участия; допустима ничья.

Сохраните исходные ответы, оценки, соответствие скрытых меток версиям и ограничения. Для отпечатков инструкций используйте исходные байты Git blob; порядок файлов и сериализация брифов описаны в `method.fingerprints` каждого отчёта. Отпечатки определяют использованные файлы, без полного контекста модели. Сравнение с запуском без навыка является отдельным экспериментом. Модельный оценщик не заменяет человеческую оценку.

В прогоне `structure-*` от 30 октября 2026 года один независимый оценщик принял 12 ответов по всем 42 критериям. В сравнении `attention-*` одна пара оценена в пользу 0.4.0, 13 дали ничью, критических ошибок не отмечено. Это отдельные ограниченные прогоны; они не подтверждают поведение во всех моделях и сценариях. Полные ответы и ограничения сохранены в JSON-отчётах.

## Автоматическая проверка

```bash
node --test scripts/prepare.test.mjs scripts/release-version.test.mjs
node scripts/prepare.mjs
```

Проверяются структура, локальные ссылки, комплектность справочников, лицензия, стабильная версия и её совпадение у переводов, однострочное JSON-совместимое описание и определения сценариев. Брифы и критерии должны быть непустыми строками; критерии передаются массивом.

У `example_outputs` проверяются явно заданные `example_constraints`: логические `no_em_dash`, `no_typographic_quotes` и неотрицательный целочисленный `max_characters` по существующей метке ответа. Неизвестные названия ограничений отклоняются. Длина считается в Unicode code points; имена площадок не задают лимиты. Точная цитата может сохранить исходные кавычки и тире.

Тест сборщика работает в изолированной временной папке: проверяет обе переносимые версии и отклонение повреждённых входных данных. Тест релизов проверяет выбор версии, повторный запуск и сохранность файлов при ошибке. Эти команды собирают файлы и проверяют упаковку; ответы модели они не генерируют и не оценивают. Подробности находятся в [руководстве разработчика](../docs/development.md).

Реакции аудитории измеряются отдельно после разрешённой публикации: сравнивайте сопоставимые окна, язык, площадку и тип материала. Записывайте только доступные показы, содержательные ответы, сохранения и репосты. Отсутствие метрики не равно нулю; рост после одной публикации не устанавливает причинный эффект начала.
