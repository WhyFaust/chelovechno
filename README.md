# Человечно

Русский | [English](README_en.md)

Навык для AI-агента, который пишет авторские тексты с понятной мыслью и живым голосом: посты, статьи, письма, сценарии, описания, названия, комментарии и ответы на них. Может написать с нуля, отредактировать черновик, адаптировать материал или найти свежую тему.

Русский в приоритете; другие языки по запросу. Тон и форма зависят от задачи и адресата. Если дать образцы своих текстов, агент будет учитывать их ритм, словарь и манеру общения.

```text
$chelovechno Найди свежую новость о городской фотографии за последние 3 дня
и напиши пост для Telegram. Читатели — начинающие фотографы.
Спокойно, с конкретикой, без рекламы и придуманного личного опыта.
```

Навык работает в вашей модели и среде. У него нет собственного сервера, API-ключа и подписки. Для свежих тем агенту нужен доступ к поиску или браузеру.

## Установка

В агент с поддержкой [Agent Skills](https://agentskills.io):

```bash
npx skills add WhyFaust/chelovechno --skill chelovechno
```

Установщик предложит выбрать агента. Для установки на уровне пользователя в Codex:

```bash
npx skills add WhyFaust/chelovechno --skill chelovechno --agent codex --global
```

Для Claude Code замените `codex` на `claude-code`; для Cursor — на `cursor`. Для всех агентов, которые поддерживает установщик:

```bash
npx skills add WhyFaust/chelovechno --skill chelovechno --agent '*' --global
```

Команда использует [Skills CLI](https://skills.sh/docs); для неё нужен Node.js с npm. Для ручной установки Node.js не нужен.

### Вручную

Скачайте репозиторий и скопируйте **всю** папку `skills/chelovechno`, сохраняя `references/` и `agents/`:

| Среда | Папка пользователя | Папка проекта |
|---|---|---|
| Codex | `~/.agents/skills/chelovechno/` | `.agents/skills/chelovechno/` |
| Claude Code | `~/.claude/skills/chelovechno/` | `.claude/skills/chelovechno/` |

`~` в Windows — каталог пользователя, обычно `C:\Users\имя`. Для другой среды используйте её документированную папку навыков. Не заменяйте существующий навык без сохранения своих правок.

Формат соответствует Agent Skills. Фактическое обнаружение и синтаксис вызова зависят от агента: в Codex — `$chelovechno`, в Claude Code — `/chelovechno`; также можно попросить написать пост обычными словами. Изменения навыков Codex обычно обнаруживает автоматически; если навык не появился, перезапустите среду. [Документация Codex](https://learn.chatgpt.com/docs/build-skills), [Claude Code](https://code.claude.com/docs/en/skills).

### В обычном чате или своей системе

Скачайте **chelovechno.md** из [релиза](https://github.com/WhyFaust/chelovechno/releases/latest). Это полная версия навыка одним файлом: основные инструкции и справочники. Приложите её к чату или используйте как инструкцию в своей системе, затем дайте задачу. Для локальной сборки файла: `node scripts/prepare.mjs`.

Один файл удобен там, где нельзя установить папку навыка. Он не добавляет модели браузер: без поиска она сможет писать по вашим материалам, но не должна придумывать свежие новости. Загрузка Markdown как инструкции зависит от возможностей конкретного чата.

### Английская версия

[README_en.md](README_en.md), [SKILL_en.md](skills/chelovechno/SKILL_en.md) и справочники с суффиксом `_en` содержат английский перевод. В релизе есть полный файл **chelovechno_en.md**. Для папки с английскими инструкциями после ручного копирования замените содержимое `SKILL.md` содержимым `SKILL_en.md`; справочники уже входят в комплект. При желании замените `agents/openai.yaml` на `agents/openai_en.yaml` для английского интерфейса Codex. Устанавливайте одну версию навыка, имя остаётся `chelovechno`.

Язык инструкций не меняет язык результата: русский остаётся языком по умолчанию, английский или другой язык можно явно указать в запросе.

## Что попросить

Навык не делит площадки на фиксированные режимы. Сначала он учитывает явно запрошенный вид текста, затем контекст разговора и способ использования. Описание ролика и текст для чтения в кадре получатся разными, даже если оба нужны для YouTube. Для новой площадки не нужно дописывать отдельный справочник.

Если контекста достаточно, агент пишет сразу. Если сказано только "для YouTube" и непонятно, нужен ли сценарий, описание или название, он задаст один вопрос с вариантами. Произвольный комплект вместо нужного результата не создаётся.

**Подпись к фото**

```text
Напиши 3 подписи для Instagram. На фото — пустой пляж после дождя.
Коротко, спокойно, без философии. Не придумывай историю поездки.
```

**Описание ролика**

```text
Описание для ролика на YouTube. В ролике показываю сборку блокнота:
выбор бумаги, прошивку и крепление обложки. Для новичков.
Без выдуманных таймкодов, ссылок и лишнего комплекта текстов.
```

**Свежая тема → готовый пост**

```text
Сам найди свежий повод о любительском беге и напиши пост для Telegram.
Аудитория — люди, которые бегают для себя. За последние 3 дня.
Объясни, чем это полезно. Источники вынеси отдельно от текста.
```

**Текст для устной речи**

```text
Теперь напиши вступление к этому ролику. Буду читать его в кадре.
Нужны только мои слова, без описания и ремарок о монтаже.
```

**Ваша манера**

```text
Вот несколько моих текстов: [образцы]. Возьми их ритм и интонацию.
Новая статья про [тема]. Аудитория: [читатели]. Материалы: [факты].
Истории и биографию из образцов в новый текст не переноси.
```

**Деловое письмо**

```text
Письмо партнёру Анне. Планируем прислать макет 12 ноября.
Если согласование затянется, отдельно предупредим об изменении срока.
Попроси подтвердить, подходит ли план. Спокойно, без выдуманной подписи.
```

**Комментарий и ответ в ветке**

```text
Напиши комментарий к этому посту: [пост]. Хочу поддержать автора,
без выдуманного "у меня было так же" и непрошеных советов.
```

```text
Помоги ответить на комментарий: [реплика]. Исходный пост: [пост].
Последние уточнения: [если есть]. Моя позиция: [что хочу сказать].
Спокойно и по существу. Верни только ответ.
```

Агент различает комментарий к публикации и ответ конкретному собеседнику. Учитывает родительскую реплику и уточнения, не повторяет уже испробованный совет. Благодарность может остаться короткой; несогласие опирается на тезис; ответ бренда не обещает выдуманный возврат, срок или выполненное действие.

**Редактура**

```text
Сделай текст живее. Сохрани цену, сроки, ссылки и все оговорки.
Верни только готовый текст: [черновик].
```

По умолчанию агент выдаёт один готовый результат. Количество, объём и структура из запроса имеют приоритет. Существенные пробелы уточняет одним вопросом с вариантами; уже известное повторно не спрашивает. Подробный разбор и статья не сжимаются до поста ради краткости.

Точные ограничения конкретного поля и способа публикации агент проверяет, когда они влияют на результат. В навыке нет таблицы вечных лимитов и обязательных схем для площадок.

Заголовок или первая фраза называют конкретную тему и причину читать дальше; продолжение раскрывает обещание начала. У шутки может быть только узнаваемая мысль, у полезного поста есть объяснение или пример. Вопрос уместен, если ответ продолжает содержание. Благодарность остаётся репликой без отдельного крючка. Просьба исправить только опечатки важнее усиления начала; гарантированный охват не обещается. [Примеры правки начала](examples/texts.md).

Для полезного поста с предложением и опроса есть необязательные варианты структуры. В первом объяснение полезно и без покупки; во втором один ясный вопрос помогает выбрать или обсудить конкретную тему. Заданный способ заказа или получения материала, включая кодовое слово, сохраняется. Если продажа или опрос не нужны задаче, они не добавляются. [Новые примеры](examples/texts.md).

## Как работает поиск

Если запросу нужна актуальность, агент сначала ищет материалы, открывает их и проверяет ключевые утверждения. Для свежих поводов обычный период составляет последние **72 часа** относительно времени запуска. Для медленной темы он может расширить окно до 7 дней, сообщив об этом. Указанный вами период имеет приоритет. Исторический обзор и исследование для статьи не ограничиваются этим новостным окном.

Агент различает дату публикации и дату события, ищет первоисточник и не считает перепечатки независимыми подтверждениями. Для обычного объявления достаточно его автора; спорные выводы требуют дополнительных оснований. Старый запуск в свежей статье не становится новой разработкой.

После результата идёт отдельная заметка для автора: время проверки, период, прочитанные источники и существенные ограничения. В устной речи источник называют словами, служебные ссылки остаются за пределами произносимого текста. Если проверка не удалась, агент сообщает об этом и предлагает дать материалы или выбрать другую тему.

Поиск запускается вашим запросом. Мониторинг по расписанию и автопубликация требуют возможностей среды и отдельной настройки.

### Опционально: Agent Reach

[Agent Reach](https://github.com/Panniantong/agent-reach) можно подключить отдельно для поиска и чтения источников, которые неудобно получать обычными инструментами. Человечно использует уже доступное дополнение при необходимости. Базовая установка навыка обходится без него.

[Как подключить и что учитывать](docs/agent-reach.md): установка по инструкции автора, проверка каналов и границы доступа. Дополнение не устанавливается автоматически. Поддержка конкретного сервиса и вход в аккаунт зависят от Agent Reach и вашей среды; доступ ко всем площадкам не обещается.

## Подход

Основной сценарий: понять задачу и формат, найти подходящую мысль или материал, написать для конкретного читателя или слушателя.

Новость объясняет, что изменилось для читателя; статья раскрывает тему; письмо помогает адресату понять ситуацию и действие; сценарий удобно произносить. Детали отбираются по смыслу, существенные ограничения сохраняются. В авторском тексте по умолчанию нет длинного тире U+2014, фразы перестраиваются по смыслу. Для кавычек используется обычный двойной символ U+0022 (`"текст"`). Точные цитаты и обязательные формулировки сохраняются. Выдуманный личный опыт и искусственная небрежность не добавляются. Источники подхода описаны в [SOURCES.md](SOURCES.md).

Для разработки нужен Node.js 22 или новее. Без установки зависимостей:

```bash
node --test scripts/prepare.test.mjs scripts/release-version.test.mjs
node scripts/prepare.mjs
```

Тесты проверяют сборщик на корректных и повреждённых данных, а также выбор релизной версии. Сборка проверяет структуру, локальные ссылки и комплектность обеих версий, затем создаёт `dist/chelovechno.md` и `dist/chelovechno_en.md`. Эти проверки также запускаются в GitHub Actions. Они проверяют упаковку, а не "процент человечности" текста. Изменения поведения проверяются на сценариях из `evals/`.

После успешной проверки `main` GitHub Actions выбирает следующую версию по сообщениям коммитов после последнего релиза, согласно [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

| Коммиты | Повышение версии |
|---|---|
| `fix:`, `perf:` | patch: `0.4.0` → `0.4.1` |
| `feat:` | minor: `0.4.0` → `0.5.0` |
| `!` перед `:` или футер `BREAKING CHANGE:` / `BREAKING-CHANGE:` | major: `0.4.0` → `1.0.0` |
| `docs:`, `test:`, `chore:`, `ci:`, `build:`, `style:`, `refactor:` без breaking change | Без релиза |

Среди всех новых коммитов выбирается наибольшее повышение. Область допустима: `fix(parser): ...`. При обычном мердже учитываются коммиты внутри PR; при squash нужен соответствующий заголовок итогового коммита.

Workflow сам обновляет `metadata.version` в `SKILL.md` и `SKILL_en.md`, проверяет сборку, сохраняет версию коммитом в `main` и публикует тег `vX.Y.Z`, ZIP папки навыка и оба переносимых Markdown-файла. Ручные правки версии не нужны. Повторный запуск не повышает её ещё раз. Для продолжения незавершённой публикации запустите workflow "Check skill" на ветке `main`; если остался черновик релиза, завершите или удалите его перед повторным запуском.

Качество текста зависит от модели, материалов и задачи. Навык не определяет авторство текста и не обещает результат в AI-детекторах. Самостоятельно найденные новости требуют проверки источников; личный опыт автора агенту всё равно нужно сообщить.
